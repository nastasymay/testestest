# Прототип исследования: Cloudflare Workers + D1

Кликабельный кабинет клиента по PDF «Прототип на немодер исследование». Два задания: найти тариф и срок действия Диадока, затем тариф Экстерна у ООО «Ромашка». Реализованы выбор организации, панели тарифов, наведение строк, продление и демонстрационный счет.

Основной вариант размещения — Cloudflare Workers со статическими ресурсами и базой D1. Яндекс Метрика и отдельный сервер не требуются. Участник открывает приглашение и вводит общий пароль; результаты доступны исследователю по отдельному паролю в `/admin`.

## Настройка публикации в Cloudflare

База пользователя уже указана в `wrangler.jsonc`:

- Worker name: `kontur-research`.
- D1 database name: `kontur-research`.
- D1 database ID: `15c0a949-fd13-4a81-a496-2883016dcf4f` (идентификатор, не секрет).
- D1 binding: `DB`.

В Cloudflare Workers & Pages подключите GitHub-репозиторий `nastasymay/testestest`, ветку `main` и задайте:

| Поле | Значение |
| --- | --- |
| Worker / application name | `kontur-research` |
| Root / Path | `/` |
| Build command | `npm ci` |
| Deploy command | `npm run deploy:cloudflare` |
| Preview builds | Выключены |
| Cloudflare Access | Выключен; авторизация реализована приложением |

Команда публикации сначала применяет SQL-миграции к D1, затем публикует Worker и ресурсы сайта. Оба шага используют авторизацию Cloudflare Builds; токены и пароли не нужно копировать в репозиторий. Повторное применение миграций сохраняет результаты. Созданному для сборки API token нужен доступ к Workers и этой базе D1. Если этап миграций сообщает об отказе в доступе, исправьте права токена в Cloudflare, не отключая проверки.

Если приложение уже создано с прежней командой `npx wrangler deploy`, откройте его Settings → Build (раздел сборки может называться Builds) и измените Deploy command на `npm run deploy:cloudflare`. Одной команды `wrangler deploy` недостаточно: она не создает таблицы D1.

После первой успешной публикации откройте **Worker → Settings → Variables and Secrets → Add**. Создайте три значения с типом **Secret**:

| Имя | Для чего | Требование |
| --- | --- | --- |
| `ADMIN_PASSWORD` | Вход исследователя в `/admin` | Свой пароль, минимум 12 символов |
| `PARTICIPANT_PASSWORD` | Общий пароль участников | Другой пароль, минимум 8 символов |
| `COOKIE_SECRET` | Подпись cookie доступа | Независимая случайная строка, минимум 32 символа, например из генератора паролей |

Сохраните значения и разверните изменения через Save / Deploy, как предлагает интерфейс Cloudflare. Эти значения — runtime secrets Worker; простая переменная процесса сборки не заменяет их. Секреты не присылайте в чат и не вставляйте в код. До настройки всех трех секретов приложение намеренно показывает «Исследование ещё настраивается» и не принимает прохождения.

Бесплатный адрес Worker отображается в карточке приложения и разделе Domains & Routes; домен покупать не нужно. Откройте `<адрес Worker>/admin`, войдите паролем исследователя, нажмите «Скопировать ссылку участника». Отправляйте эту ссылку вместе с паролем участника; можно отдельными сообщениями.

Перед настоящим исследованием пройдите оба задания на опубликованном домене, проверьте путь и результаты в панели и экспорт CSV. Локальные тесты не подтверждают публикацию или права доступа в вашем Cloudflare.

## Защита доступа

Приглашение содержит случайный 256-битный ключ. Оно само по себе не открывает прототип: нужен также общий пароль участника. Cookie подписаны сервером, HttpOnly, SameSite и Secure на HTTPS. До входа закрыты страница, JavaScript прототипа и API прохождений. Прямой запрос `/index.html` не обходит защиту: все ресурсы проходят через Worker (`assets.run_worker_first=true`).

Приглашение не дает доступа к панели исследователя. Вход в панель — отдельный пароль. Попытки подбора паролей ограничиваются через D1 и учитываются по хешу адреса клиента, без сохранения самого IP в результатах исследования. Сайт отдает `X-Robots-Tag: noindex, nofollow, noarchive`, `robots.txt` с запретом индексации и `Referrer-Policy: no-referrer`.

В панели можно отключить исследование или создать новое приглашение. Это отзывает прежнюю ссылку и действующие cookie участников; результаты остаются в D1. Смена пароля участника также отзывает его cookie, а смена пароля исследователя — сессии панели. Любой, кому передали и действующую ссылку, и общий пароль, сможет участвовать; личность участника не проверяется.

## Результаты исследования

Панель обновляется каждые 10 секунд. Доступны сессии, клики, время, путь участника, результаты двух заданий, необязательный короткий ответ и экспорт CSV/JSON. Видео экрана не записывается.

- «Выполнено» — участник сам отметил завершение; это не автоматическая оценка правильности.
- «Экран открыт» — нужная панель посещена в ходе соответствующего задания.
- Время включает паузы и время в других вкладках; переключения фиксируются отдельно.
- Незавершенные сессии остаются как «В процессе / прервано».
- CSV содержит по строке на задание; JSON — также все события с координатами и временем.

Клиент сохраняет сессию и очередь в `sessionStorage`, повторяет отправку при восстановлении связи. Перезагрузка продолжает прохождение. Дождитесь «Данные сохранены» перед закрытием вкладки. При закрытии вкладки во время длительного отсутствия связи недоставленные события могут потеряться. Значения полей не пишутся как клики. Реальные платежи, отправка писем и ввод реальных реквизитов отключены.

Вкладки «Будущие» и «Архив» — пустые состояния, поскольку их содержимого в PDF нет. Полные сценарии показаны для «Только мои» и ООО «Ромашка»; данные других доступных организаций демонстрационные. Разделы за пределами сценария показывают сообщение об ограничении прототипа. Названия и даты зафиксированы по макету, а не по сегодняшнему дню.

Срок хранения определяет исследователь. Удаление отдельных прохождений через UI пока не реализовано. В Cloudflare D1 доступны управление базой и экспорт; перед удалением или изменением схемы сохраняйте резервную копию. Бесплатные лимиты и условия проверьте в актуальном тарифе Cloudflare.

## Разработка и проверки

Используйте существующий checkout. Каждая облачная задача уже изолирована; отдельный Git worktree не требуется, если пользователь его не запросил. Требуется Node.js 24+.

```sh
npm ci
npm test
npm run test:cloudflare
```

`npm test` проверяет исходный Node-сервер. `test:cloudflare` запускает настоящий локальный Worker через Wrangler и локальную D1, применяет миграции, проверяет вход по ссылке и паролю, изоляцию сессий, атомарность записи, повторы, выгрузку, отзыв доступа и сохранность после перезапуска. Удаленная база при тестировании не затрагивается. Проверочные пароли используются только во временной среде и не применяются на хостинге.

Для полной проверки в браузере нужен Chromium и Playwright (работающему сайту они не нужны):

```sh
npm install --prefix /tmp/prototype-browser --cache /tmp/prototype-npm-cache @playwright/test
PLAYWRIGHT_MODULE=/tmp/prototype-browser/node_modules/@playwright/test/index.mjs npm run test:cloudflare
```

Тесты проверяют оба задания, мобильную версию, продление, счет, потерю связи и восстановление очереди, панель и экспорт. По умолчанию Chromium — `/usr/bin/chromium`, путь можно изменить через `CHROMIUM_PATH`. Скриншоты создаются в `/tmp/prototype-artifacts`.

Для ручного локального запуска создайте игнорируемый `.dev.vars` с тремя локальными секретами, затем:

```sh
npx wrangler d1 migrations apply kontur-research --local
npm run dev:cloudflare
```

Ресурсы и таблицы локальной D1 хранятся в `.wrangler/`. `.dev.vars`, локальные данные, логи и пароли не включать в Git. Live-процессы нужно запускать заново после восстановления среды. Публикация облачной среды Codex не публикует сайт Cloudflare.

В проекте также сохранен исходный Node-вариант (`npm start`, Dockerfile). Он использует локальную SQLite и вход участника по секретной ссылке; для окончательного варианта со ссылкой и общим паролем используйте Worker. Данные из локальной Node-базы не переносятся автоматически в D1.
